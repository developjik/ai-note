# M5 설치·수용 검증 프로토콜 (클린 VM 매트릭스 + 비개발자 5인)

> 계획 §9 M5 검증: 가이드 기반 클린 VM 설치 매트릭스, 중재 비개발자
> 사용성 테스트 5인(E2E 6단계 완주 + 어휘 위반 0회, 화면 녹화·체크리스트),
> 업데이트 감지 녹화. 자동화 가능한 부분(업데이터 감지 e2e·어휘 감사)는
> 통합 테스트로 증명 완료(m5_scenarios 4/4) — 아래는 사람·실기기 절차.

## 1. 클린 VM 설치 매트릭스 (각 OS 1대 — 스냅숏 복제 후 시작)

| 단계 | macOS (Apple Silicon, 최신) | Windows 11 (깨끗한 계정) |
|---|---|---|
| 0. 사전 상태 | 앱 미설치·git/Node 개발도구 없음(비개발자 환경) | 동일 |
| 1. 다운로드 페이지 접근 | Pages URL → 안내 문구 표시 확인 | 동일 |
| 2. dmg/exe 받기 | Releases에서 dmg | Releases에서 exe |
| 3. 설치 | 응용프로그램 폴더 드래그 | 설치 마법사 완료 |
| 4. 첫 실행 경고 | "확인할 수 없음" → 시스템 설정→개인 정보 보호 및 보안→그래도 허용(1회) | "Windows가 PC를 보호했습니다"→추가 정보→실행(1회) |
| 5. 초대장 연결 | Pages /invite에서 생성한 초대장+암호로 온보딩 완료 | 동일 |
| 6. 노트 작성→검토→반영 | E2E-1..6 흐름 완주 | E2E-1..5 완주(AI 단계 제외 — §3 Windows v1 제한 참조) |
| 기록 | 각 단계 스크린 녹화 + 소요 시간 | 동일 |

통과 기준: 두 OS 모두 6단계 완주, 경고 우회가 안내 그대로 1회로 끝남,
개발 도구(git/Node)가 없어도 전 과정 가능함(P3 증명).

## 2. 비개발자 사용성 테스트 (5인, 중재자 동반)

- 모집: 개발 직무 아닌 팀원 5명(온보딩·워크스페이스·검토 각각 담당 예정자 우선).
- 준비: 관리자가 초대장 생성(Pages), 참가자 각각 클린 프로필.
- 과제(중재자는 안내만, 조작은 금지):
  1. 초대장으로 팀 연결(온보딩 화면만 보고)
  2. 새 노트 작성 후 저장 → "검토에 보냈어요" 확인
  3. 다른 참가자의 변경을 검토함에서 나란히 보기로 확인 후 반영
  4. 문서 검색으로 과거 회의록 찾아 그 위치로 점프
  5. 이미지 넣기로 자료 첨부
  6. AI 작업 한 건 요청 → 검토함 카드에서 "AI 작업" 표시 확인 후 반영
- 측정: 완주율(6/6), 구두 질문 수, 어휘 위반 노출("커밋/푸시/충돌" 등을
  사용자가 읽거나 말한 횟수 — 0회 목표), 첫 저장까지 시간.
- 기록: 화면 녹화 + 체크리스트 시트(참가자별) 저장.

통과 기준: 5인 전원 6단계 완주 + 어휘 위반 0회. 미달 시 화면 녹화 기준
개선 후 재시도(최대 2라운드).

## 3. 업데이트 감지 녹화 (v0.9→v1.0)

1. v0.9 설치 상태에서 설정 화면 열기 → "새 버전(v1.0.0)" 안내 표시 확인.
2. 다운로드 페이지 버튼 → 페이지 도착 확인(minisign 서명 검증 성공 상태).
3. v1.0 dmg/exe 덮어 설치 → 정상 기동 확인.
- 자동 증명: m5_update_detect_e2e_signature_verified(wiremock + minisign
  공개 벡터) — 서명 검증 true 경로 포함. 녹화는 배포 후 수행.

### Windows v1 제한(위협모델 §5 이행 고지)

v1의 OS 샌드박스 강제(L2)는 macOS Seatbelt만 구현되어 있다. Windows에서는
안전 실행 장치 미지원(`unsupported_platform`)으로 **AI 작업이 안전하게 거부
기동된다**(fail-closed — 사용자에게는 "안전 실행 장치는 아직 준비 중"
안내). 따라서 Windows 클린 VM 매트릭스의 6단계는 **AI 작업 제외**한
E2E-1..5(연결·작성·검토·반영·이력) 완주이며, AI 단계는 AppContainer/제한
토큰 동등 증명(CI 매트릭스) 후 해금된다.
