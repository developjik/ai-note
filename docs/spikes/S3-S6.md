# S3 — Tantivy 한국어 바이그램 전문 검색

**상태: 검증 완료** — `cargo test -p spike-tantivy-ko` 4/4 통과 (tantivy 0.22.1)

## 핵심 발견
tantivy 0.22에 **내장 `NgramTokenizer`** 가 있어 커스텀 토크나이저 어댑터가 불필요하다:
```rust
NgramTokenizer::new(2, 2, false) + LowerCaser 필터 → "ko_bigram" 등록
```
교체 지점(P5)은 `register_korean_bigram()` 함수 하나로 고정 — v2 lindera-ko 이관 시 이곳만 교체.

## 검증 결과
| 항목 | 결과 |
|------|------|
| 한국어 부분일치 (형태소 없이) | "예산"→회의록 문서, "습관"→독서노트 적중 ✓ |
| 파일명+제목+내용 혼합 질의 (F24) | 제목어·내용어 모두 정확한 문서 적중 ✓ |
| 증분 색인 (추가 문서 즉시 검색) | 커밋+reload 후 적중 ✓ |
| 규모 (3,000문서) | **색인 0.4s · 질의 5ms · 인덱스 0.3MB** ✓ |

## 결론
- F33 규모 상한(팀 10명·문서 수천 개)에서 성능 목표(검색 p95 < 300ms, M5)를 여유로 상회.
- 무사전 바이그램의 한계(조사 결합 오매칭 가능)는 실사용 품질 모니터링 대상이며, 형태소 정확도 필요 시 v2 토크나이저 스위치(lindera-ko)로 교체 — 스키마 호환은 리인덱싱으로 처리(문서 수천 개 = 전량 재색인 수 초).

# S4 — 초대장 코덱 (구현체 = ai-note-core::invite)

**상태: 검증 완료** — `cargo test -p ai-note-core` invite 6/6 통과

## 구현 (crates/ai-note-core/src/invite.rs)
- 레이아웃: `"AINV" | u8 ver | nonce[12] | salt[16] | len(u32 LE) | AES-256-GCM ciphertext` → base64url
- 키 유도: PBKDF2-HMAC-SHA256 200,000 회 + AES-GCM(AAD=매직+버전 — 버전 위조 방지)
- 페이로드: `{ghp, repo, display}` — classic PAT repo 스코프(A7)·자동 생성 저장소명(A3)·표시명 캡처(E5)
- 버전 필드 전방 호환(Codex v2+·코덱 진화 대비), 키 메모리 `zeroize`

## 검증 항목
왕복 성공 ✓ / 암호 오류 → DecryptFailed ✓ / 위변조 → GCM 인증 실패 ✓ / 가비지 입력 안전거부 ✓ / 결정적 인코더 파라미터 벡터 ✓ / 미래 버전 거부 ✓

## Pages 공유 계약
`encode_deterministic()`가 고정 salt/nonce 재현을 제공 — Pages JS가 `TEST_VECTORS` 파라미터 세트로 동일 문자열을 만들어내는 상호운용 테스트를 M1 온보딩 파이프라인에 포함한다(P9와 동일한 '문서 근거 확보 전 표현 축소' 원칙 — 벡터는 민감한 암호문이 아니라 파라미터 세트로 유지).

# S5 — 무서명 업데이터 (감지→검증→수동 재다운로드)

**상태: 설계 검증 완료 (라이브 e2e는 M5 — 계획상 M5 산출)**

## 전제 (사용자 확정)
v1 무서명(Q1) + 업데이터 의미 변형 승인(P7): **설치 시 1회 보안 경고 우회 + 업데이트는 앱 내 감지·설정 버튼 수동 실행.**

## 설계 결론
1. **감지**: GitHub Releases latest API(`ETag` 조건부 요청, R3 예산 안) — 버전 비교는 semver.
2. **검증**: minisign(Ed25519) 공개키를 앱에 내장, 인스톨러·checksum 서명 검증 후에만 안내 문구에 "검증됨" 표시. 무서명 OS 경고와 별개로 **위변조 방지는 앱이 보장**한다.
3. **실행**: 설정 화면 "업데이트" 버튼 → 다운로드 → minisign 재검증 → 설치 프로그램 실행(macOS: dmg 마운트 안내/Windows: NSIS 실행). 자기 교체·자동 재시작 없음.
4. **재경고 현실**: 새 버전 첫 실행 시 OS 경고가 재발할 수 있다(무서명 비용, Q1 승인 범위). 버튼 UX는 "보안 안내 한 번 더 눌러주세요" 가이드를 함께 표시. S5 라이브 e2e(M5, v0.9→v1.0)가 재경고 여부·단계 수를 실측해 다운로드 페이지 가이드에 반영한다.
5. **v2**: 코드서명 확보 후 Tauri updater 자기 교체로 복귀(ADR Follow-ups).

# S6 — 3층 게이트 강제 스택 실현성

**상태: macOS 실증 완료 / Windows 설계 게이트는 M3 CI 매트릭스에서 증명**

## macOS 실증 (sandbox-exec, 이 개발기계)
### L2 프로파일 도출
- **strict `(deny default)` 프로파일은 claude CLI(Bun 런타임)를 즉시 죽인다**(exit 134/SIGABRT 재현) — fork·mach·shm 등 런타임 요구가 기본 거부에 걸림. **P8 우려의 실물 재현.**
- **채택: 허용형 프로파일** `(allow default)` + `(deny file-write*)` + 예외 subpath(`~/.claude`, 작업 스크래치):
  ```scheme
  (version 1)
  (allow default)
  (deny file-write*)
  (allow file-write* (subpath "/Users/<user>/.claude"))
  (allow file-write* (subpath "<샌드박스 작업사본>"))
  ```
### 실측 결과
| 검증 | 결과 |
|------|------|
| 프로파일 내 claude CLI 정상 동작 (P8 긍정 단언) | `SANDBOX_OK` 응답, exit 0, 스트리밍 정상 ✓ |
| 샌드박스 내 볼트 경로 쓰기 | `Operation not permitted` — 차단 ✓ |
| `~/.claude` 쓰기(로그인 상태·세션 유지) | 허용 ✓ |

**결론: L2가 claude를 깨뜨리지 않으면서 정본 볼트 쓰기를 차단하는 프로파일이 실재한다.** macOS 구현체는 이 프로파일 생성기(작업사본 경로 주입)가 된다.

## 3층 스택 확정 (Architect pass-2 반영)
- **L1 — CLI 권한 플래그(게이트 요구사항으로 승격)**: S1 검증대로 `--permission-mode`/도구 제한 플래그로 자식 자신의 권한을 먼저 좁힌다. 앱이 L1 플래그 없이는 에이전트를 기동하지 않는다(게이트 요구사항).
- **L2 — OS 샌드박스**: 위 프로파일(macOS Seatbelt). Windows는 AppContainer/제한 토큰 — M3에서 CI 매트릭스로 동등 증명(설계 동일: 쓰기 ACL 거부 + 예외 경로).
- **L3 — 탐지**: 작업사본·정본 볼트 경로의 파일 이벤트 감시(fnotify/FSEvents/ReadDirectoryChangesW)로 우회 시도 탐지→프로세스 종료+일상 언어 알림.
- **보장 범위 문구(정직한 AC)**: 구조 검증은 **main 무결성**(승인 없이 원격 main 반영 불가 — 토큰 격리+머지 원자성)을 보장한다. 샌드박스 강제는 층별로 탐지·차단하나 로컬 동일 사용자 권한의 기밀성(볼트 파일 읽기)은 위협 모델 문서에 명시된 범위 밖이다(docs/threat-model.md — M3 종료 전 architect 리뷰 게이트).
